# Atomic Notes

> **Example note.** It shows the templates, frontmatter, links, and index working together. Delete it (and update `related:` links that point at it) once you have added your own notes.

## Overview

An atomic note holds exactly one idea, so it can be linked to from anywhere that idea matters.

## Definition

A note is atomic when its title states a single idea and everything in the note serves that idea. A note that needs "and" in its title is usually two notes.

## Key Claims or Principles

- **Links get precise:** a link to a one-idea note says exactly what is being referenced.
- **Search gets sharper:** a one-line summary can describe the whole note, so the Map of Content (`index.md`) stays accurate.
- **Reuse gets cheap:** the same note supports many patterns and workflows without being copied.

## Why It Matters

Big notes hide ideas inside them. An agent that selects notes from the index cannot see an idea buried in paragraph six of a note about something else.

## Examples

### Example 1: Splitting a meeting write-up

A long "Q3 planning notes" file becomes three notes: a concept (why the team limits work in progress), a technique (the checklist used to cut scope), and a case study (what happened this quarter). Each links to the others.

### Counter-Example (What NOT to Do)

A single "everything about onboarding" note that grows for a year. Nothing links to it precisely, and its summary can only say "notes about onboarding".

## When to Use This Concept

- When drafting any note in the core buckets
- Not for `_inbox/`, where raw notes are allowed to be messy
